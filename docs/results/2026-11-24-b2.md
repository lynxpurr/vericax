# VeriCAx v0.2 capability results — B2

- **Status**: published 2026-11-26, corrected 2026-11-27; B2 ran 2026-11-23/24
- **Suite**: v0.2.0-alpha; split `v0.2-cae-cli-25` (18 tasks) plus `v0.2-cae-cli-merged` (4 tasks)
- **Stacks**: dsh 0.2.1-rc.5, opencode 1.19.5 (Bailian variant), openclaw 2026.9.9 (Bailian variant)
- **Model**: `deepseek-v4.1-flash-1017` via the Aliyun Bailian Token Plan gateway
- **Design**: n=3 real episodes per (task, stack); 198 native-scored episodes; 19 infra episodes retried and excluded from the means
- **Harness**: episodes were recorded with the fixed per-episode proxy socket (PR #31, `e4efcf2`); the aggregation tool is at `643b417`; the 2026-11-27 correction was produced with `scripts/capability_report.py --reextract-cost`

## Method

Each stack ran the same 22 task packages with `--kind capability`, `--run-mode rerun`
and `--runs 3`. opencode and dsh's first half ran at `--parallel 2`; openclaw and
the remaining dsh batches used `--parallel 1` after host memory pressure and VM
control-channel resets. Retries are infra-only (up to two attempts per cell) and
are reported, never scored. Capability failures are data.

**Correction (2026-11-27).** Two figures changed and no score did. (1) The first
publication counted 16 infra episodes out of 214 (7.5%), because only the episodes
recorded by the batch runs were counted; three dsh manual retries that had failed
again as infra were missing. With them it is 19 of 217 (8.8%): dsh 12, opencode 4,
openclaw 3. Two dsh cells move with them. FEniCS design-optimization goes from
549,357 to 584,427 tokens per task and FEniCS open-environment from 314,865 to
448,389; their active-time medians (771 s and 584 s) now include the failed
retries. (2) openclaw's token usage was missing at run time. It was re-extracted
from the stored agent streams with the fixed extractor: a cost re-score, not a
rerun. All 69 openclaw episodes read. The per-task table is unchanged. On the
same day the `cache-read/task` column was added to the matrix; no score and no
token/task value changed.

**Root cause of the infra episodes (2026-11-27).** The 19 infra episodes were
sandbox losses: the guest's kernel panicked because PID 1 faulted on a
shadow-stack access in the self-built images, with or without an agent. The
mechanism, the fix (`clearcpuid=519` in the three image recipes, released in
v0.2.3-alpha) and its validation are in
`docs/lessons-2026-11-27-sandbox-loss.md`. B2 predates the per-episode guest
console, so these 19 episodes carry the runtime's loss record but no console
log; every later console-logged loss showed this panic. The numbers below are
unchanged: they were measured on the images without the fix.

Scores are the task's native evaluator output: `0/1` for `exact_match` tasks and
a `0–1` quantified score for design-optimization tasks.

`tree_version` is the per-task package digest; all episodes of a task share it.
`n=3` reports a range, not a confidence interval. The experiment uses one model
and three stacks; it is not a ranking beyond the table below.

Cost is reported as tokens per task. The gateway is a subscription plan with no
USD estimate, so `$/task` is `n/a` rather than an imputed price. Tokens per task
count prompt plus completion tokens; cache reads are reported separately
(`cache-read/task` in the matrix and the table under Cost and wall time).

  1.000, open-environment 1.000, software-selection 0.583. It is also the most
  expensive (21.2M measured tokens, 8.75 h; 90.8M with cache reads).
- **opencode is the efficient stack**: FEniCS single-execution 1.000,
  design-optimization 0.912, 2.8M tokens. It is weaker on cross-stage
  consistency (0.556) and software-selection (0.417).
- **openclaw is the weakest overall** (design 0.581, software-selection 0.333),
  but still solves FEniCS observation perfectly (1.000). Its token usage was not
  read at run time; re-extracted from the stored streams it used 3.76M
  tokens, between opencode and dsh.
- **software-selection is the most discriminating capability**
  (0.583 / 0.417 / 0.333 on the merged image).
- **FEniCS tasks are near the ceiling** for these stacks; harder FEniCS items
  are needed before that solver separates stacks.

Six task-cells are all-zero across the three runs: `calculix/task-0004`
(dsh, openclaw), `calculix/task-0010` (dsh), `cross-solver/task-0003`
(openclaw), and `cross-solver/task-0005` (openclaw, opencode). Spot checks of
the scoring-side debug records show boundary/load application, incomplete
delivery, or provenance-selection failures. The gold and fake-smoke paths pass
for these packages and the audit records are MISS-free, so these are capability
failures, not verifier defects.

## Caveats

- **Single model, three stacks, n=3.** Do not read statistical significance or
  a stable ranking into cells whose ranges overlap.
- **Infra rate**: 19/217 (8.8%). dsh accounts for 12 of them, mostly FEniCS
  runs. The first publication said 16/214 (7.5%) and missed three dsh manual
  retries that had failed again. The retries are recorded in the internal run
  data.
- **Wall time is not a clean stack comparison**: opencode and dsh's first half
  ran at parallel 2; openclaw and the remaining dsh batches used parallel 1 to
  keep the host stable.
- **openclaw tokens are a re-score**: the usage envelope was not read at run
  time (PR #38 fixed the extractor). The column comes from the stored agent
  streams, not from a rerun.
- **Cache reads are usage, not a price**: the plan's billing of cached tokens
  is not published here; the column shows how much of what the gateway served
  was a cache read.
- **Raw episodes are not in this repository.** This document is the aggregate;
  the per-task `tree_version` and image sha above identify the audited tree.
