# Lessons — EngiWorld audit calibration (2026-11-19)

These are the durable lessons that drove the 2026-11-19 spec changes. Evidence is
in the external EngiWorld research workspace (report §11/§12,
`results/PHASE-B.md`); the requirements are encoded in the specs, not in this
file.

## 1. A reference answer is not evidence until the reference input reproduces it

Three CalculiX tasks (05/17/19) shipped a GT summary whose displacement was
**8.444x smaller** than the shipped GT deck's own `.dat`; task-04's tie faces and
task-06's load face were wrong. A model can be marked wrong while matching the
shipped deck.

**Requirement:** L0 reference self-check (`spec/02`). Replay the shipped
`ground_truth/*.inp`, reproduce the shipped summary, or the task package is
invalid. Add it to the audit cases.

## 2. Re-scoring is not a rerun

The audit re-scored the original run to **9/20**; the actual patched deepseek
rerun was **8/20**. The re-score assumed 06/09 would pass (they did not) and
missed 07 (it did). A re-score is an estimate, not a measurement.

**Requirement:** `run_mode` (`rerun`/`rescore`) and `tree_version` in the result
schema (`spec/03`); never compare a re-score as a rerun; rerun on the patched
tree for any model comparison.

## 3. Benchmark repair can dominate the model effect

Same deepseek model: 2/20 on the original tree → 8/20 on the patched tree (+6).
The second model (max-tier) added only task-06 and task-09 (+2). Attributing the
2/20 → 10/20 change to model capability would be wrong.

**Requirement:** decompose every comparison into repair effect and model/tier
effect; label the tier; n≥3 for conclusions (`spec/03`, `spec/05` Phase 1.5).

## 4. Exact-string verifier checks create false negatives

Task-09 required the literal `,,5.0,1.0e-5`; the agent wrote the equivalent
`1,8,5.0,1.0e-5`. Task-12/18 rejected a summary header even though the numbers
were correct.

**Requirement:** `valid_input` does numeric checks only; summary parsing tolerates
headers/blank lines; classify `equivalent_but_rejected` as a verifier defect
(`spec/02` §5).

## 5. The CLI artifact-write policy is a first-write-wins trap

The runtime rejects direct writes/rewrites to scored artifacts. qwen3.8-flash
(21 calls) and glm-5.3 (18 calls) looped on task-01 in CGX/CLI-policy probes;
qwen4 wrote once and passed in 7 steps. A wrong first deck cannot be easily
rewritten.

**Requirement:** record `artifact_write_rejected`/`agent_stalled`; do not score
it as capability 0; decide whether versioned input files are allowed
(`spec/04`, `spec/08` §11, `spec/09` §9). Current contract is unchanged.

## 6. n=1 variance is large; pilot before the full run

task-01 took 7 steps / 9.7 min in the qwen4 pilot, but 27 steps / 30.7 min in the
full run. Two models were aborted on the pilot before the 20-task run.

**Requirement:** exploratory n=1 only; n≥3 for rankings; pilot one task before a
full batch (`spec/03`, `spec/05`).
